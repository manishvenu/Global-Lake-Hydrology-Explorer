# GLHE caveat rules

These GeoJSON files are [queryearth](https://github.com/CROCODILE-CESM/queryearth)
rule files (format `"queryearth": "0.8"`). `GLHE/CLAY/caveats.py` loads them and
asks which rules apply to a lake (its polygon), the date range of its data and
the data products in it. CLAY writes the matches to `{lake}_caveats.json` in the
lake's output folder, and LIME shows them in the **Caveats** tab.

| File | Applies to | Source |
|------|------------|--------|
| `era5-land.geojson` | ERA5-Land | Vendored, unmodified, from vizqueryearth |
| `glhe.geojson` | ERA5-Land, CRUTS, NWM (dimension `product`) | Written for GLHE |

## glhe.geojson (ours)

Notes about how GLHE itself uses each product (grid resolution, coverage, record
length). Every rule is scoped by the `product` label (`ERA5-Land`, `CRUTS`,
`NWM`, as in the CSV column names). Resolution notes are also scoped by
`lake_area` in km2, which `caveats.py` computes from the lake polygon.

Most rules only show when the lake's CSV has a column for their product. A rule
that explains why a product is *missing* (such as `GLHE/NWM002`, "NWM covers the
contiguous US only") must be listed in `COVERAGE_RULES` in `GLHE/CLAY/caveats.py`; it is
then checked for every known product.

To add a note, copy an existing feature, give it a new unique `name`/`id`
(`GLHE/...`), and run the tests. A rule file only holds data: no code runs.

## Adding another rule file

1. Put the `.geojson` file in this folder.
2. Add an entry to `RULE_FILES` in `GLHE/CLAY/caveats.py` saying which GLHE
   products it applies to.
